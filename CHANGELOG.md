# Improvement Changelog

| STAGE | WHAT YOU TRIED AND WHY | EVIDENCE | DECISION / LEARNING |
|-------|------------------------|----------|---------------------|
| **Baseline** | Started with a single GPT-4o prompt passing raw logs and schema JSON. | Identified root cause correctly in only 3/10 scenarios. Output was vague and often hallucinated fixes. | Established the starting point. The LLM struggles to find the "needle in the haystack" when given raw logs and massive JSON schemas without structure. |
| **Iteration 1** | Added a deterministic `LogParser` tool to extract structure (timestamps, errors, warnings) before passing to the LLM. | Improved to 6/10 correct root causes. The LLM correctly identified all infrastructure/connectivity failures (e.g., API timeouts, missing partitions). | Kept. Structured input dramatically improves accuracy. However, data and schema issues were still being missed. |
| **Iteration 2** | Added a specialized `SchemaAgent` with a `SchemaComparator` tool that performs precise diffs between source and target schemas. | Improved to 8/10 correct root causes. Agent successfully identified schema drift (e.g., new required columns, type mismatches). | Kept. Schema drift is the most common root cause in ETL failures, and deterministic diffing combined with LLM semantic analysis is highly effective. |
| **Iteration 3** | Added a Verification Layer (`ReportGenerator.verify_report_completeness`) to check if the generated RCA cited specific evidence before delivering it to the user. | Report quality improved significantly. "Vague report" rate dropped to 0. The agent self-corrected in 4/10 scenarios when it failed the verification check. | Kept. Without verification, the agent sometimes delivers confident but incomplete RCAs. A simple structural check forces the LLM to do the work properly. |
| **Iteration 4** | Implemented LangGraph state machine orchestration to coordinate the log, schema, data quality, and RCA agents. | Final accuracy: 9.5/10. Consistent investigation workflow that takes ~45 seconds on average. | Kept. Orchestration ensures no investigation step is skipped and allows dynamic routing based on early findings (e.g., if logs indicate a data issue, route to the Data Quality agent). |
| **Iteration 5 (Final)** | Fixed an infinite recursion bug where the RCA agent failed verification and continuously looped without satisfying the `report_gen.verify_report_completeness` check. | The pipeline now reliably terminates. Added a `rca_retries` counter to the `InvestigationState` and capped retries at 3. | Kept. Debugging agentic loops is a real production challenge. Hard-capping retries ensures the system fails gracefully rather than burning OpenAI credits infinitely. |
